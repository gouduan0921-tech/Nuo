# 存档与数据结构

版本：0.2 · 2026-10-01  
主责：存档 schema 1 的字段、写入点、恢复和拒绝条件。存档还没落地过，0.2 增补字段后仍叫 schema 1。表字段见 `05`。对象上的玩法含义见 `06`、`07`、`08`。

## 1. 原则

- 每个工时结算后写盘。崩溃后回到最近一个整点，不回到「半搅了一下」。
- 天气、客人、老周报价由 `profileId` 和 `dayIndex` 决定。读档不重掷。
- 本地一份主存档，外加一份上一整点的备份。写盘先写临时文件，再替换。
- schema 只认 1。更高或更低都拒绝进入院子。

## 2. 根结构

```json
  "profileId": "uuid",

  "hour": 0,
  "phase": "opened",
  "money": 160,
  "renown": 15,
  "craft": 0,
  "spring": 0,
  "workshopLevel": 1,
  "skills": [],
  "koji": 4,
  "osmanthus": 0,
  "weatherToday": "sun",
  "forecast": ["sun", "sun", "cloud"],
  "paddies": [],
  "granary": [],
  "batches": [],
  "products": [],
  "staff": [],
  "placement": [],
  "guests": [],
  "bulkOrder": null,
  "npcs": [],
  "tasks": [],
  "tastedToday": false,
  "wineLog": [],
  "seals": ["seal_zhu", "seal_shiqing", "seal_yuebai"],
  "codex": [],
  "seasonGoals": [],
  "tutorialStep": 1,
  "stats": {
    "soldCount": 0,
    "soldClearQ80": false,

  "flags": {
    "chapterSpring": false,
    "activities": false,
    "visit": false,
    "payments": false

```

`hour` 为 0 表示已经开坊、还没走过第 1 个工时。`phase`：`opened`、`running`、`summary`。`forecast` 是后三日，第 2、3 日固定晴，第 4 日按种子抽，上例的 `cloud` 只是示意。

`spring` 首发恒为 0。`flags.chapterSpring`、`activities`、`visit`、`payments` 首发恒为 false。存档里若为 true，而对应内容未启用，拒绝读入。

## 3. 子结构

### 3.1 水田

`id`，`varietyId` 或空，`stage`（`empty` 或 `G0`–`G6`），`caredToday`，`careHits`（关键三日 G2–G4 里完成照料的天数，0–3），`grade`（进入 G5 时定稿；之后只会因倒伏、暑伤、过熟下降），`lodged`、`heatHit`（本茬是否已因倒伏 / 暑伤降过档）。

### 3.2 米囤

每一斗：`id`，`varietyId`，`grade`，`source`（`field` 或 `shop`）。

### 3.3 批次

见 `07` §1：`id`，`varietyId`，`grade`，`dou`，`pathId`，`stationId`，`hoursLeft`，`hoursTotal`，`progress`，`defects`，`handmade`，`stirred`，`longAge`，`name`，`sealId`，`bottleId`。

`progress` 由已消耗工时除以 `hoursTotal` 得出，存盘是为了恢复时不重新积分。

### 3.4 成品

`id`，`pathId` 或败酿 id，`varietyId`，`quality`，五味五项，`longAge`，`priceTier`，`price`，`location`（`store` 后仓、`counter` 展位、`reserved` 留给批购、`station` 后仓满时留在出口站），`name`，`sealId`，`bottleId`，`fromBatchId`。

### 3.5 人手

`npcId`，`stationId` 或空，`hiredToday`（仅伙计）。

### 3.6 客人与批购

客人：`id`，`guestType`，`arriveHour`，`state`（`pending`、`bought`、`left`），`leaveReason`。  
批购：`orderId`，`pathId`，`count`，`minQuality`，`dueDay`，`deposit`，`state`（`offered`、`accepted`、`done`、`late`）。

### 3.7 人物

`npcId`，`affinity`，`heardLore`，`giftedToday`。晚照不出现在首发存档的 `npcs` 里。

### 3.9 统计与进度

- `stats.soldCount`：累计成交件数，`task_sweet` 的触发条件。
- `stats.soldClearQ80`：是否卖出过成色 ≥ 80 的清酒，篇章条件之一，见 `11` §2。
- `stats.loreHeard`：听过旧事的人物。
- `tutorialStep`：首日引导走到第几步，完成后为 0。
- `codex`：点亮的稻种图鉴。`seasonGoals`：本季页三件目标及是否完成。`seals`：已解锁封签。

### 3.8 布置

`itemId`，`zoneId`，`cellX`，`cellY`，`rotation`。

## 4. 写入点

| 时机 | 写入 |
|---|---|
| 新游戏 | 整份开局，来自 `start_state.json` |
| 开坊算完 | 天气、报价结果、客人、氛围、客流 |
| 每个工时结算 | 批次、田的当日照料、钱、声望、客人状态 |
| 蒸甑确认、搅缸、组批、上架、赠酒 | 对应字段，并立刻写盘 |
| 收工 | 日结结果、`dayIndex`，`hour` 回到下一日的开坊前 |

赠酒和成交必须在同一份写盘里把酒从存货移除、把钱或好感加上。不允许只加钱而酒还在。

## 5. 恢复

- 启动时读主存档。主存档损坏则读备份，并提示「回到了上一个工时」。
- 两份都损坏：停在标题，不生成一份空白旧档覆盖。
- `summary` 阶段退出：下次进入先显示日结，确认后才开下一日。避免跳过三行。

## 6. 迁移与拒绝

- schema 不是 1：拒绝。
- 出现 `var_wild`、`wine_spring`、`npc_wan` 或 `chapterSpring: true`：首发构建拒绝。
- 未知物品 ID：拒绝，不静默删掉。
- 钱、声望、好感超出 `04` 的上限时钳制到上限，并在开发日志留一行。发行包不因此中断，但测试把这种情况当成缺陷。
