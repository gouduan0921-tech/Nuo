# 活动与运营接口

版本：0.2 · 2026-10-01  
主责：节日活动以后能改哪些数。默认全部关闭。客流倍率上限见 `04` §14。

## 1. 目的

中秋、春节一类节日以后可以用同一套酿造链做短活动：多一点桂花、多几位游客、多一枚封签。活动不新做一条工序，不缩短发酵。

## 2. 允许修正的项

`activities.json` 的 `modifiers` 只能出现这些键：

| 键 | 作用 | 限制 |
|---|---|---|
| `trafficMul` | 乘在客流上 | 单活动 ≤ 1.2；与圩日叠乘后 ≤ 1.8 |
| `guestWeightAdd` | 给某个已有客人类型加权 | 不新增客人种类 |
| `supplyExtraOsmanthus` | 老周当天多几朵桂花 | 单价仍用 `04` |
| `sealUnlock` | 临时多一枚封签色 | 不改成色 |
| `fairToday` | 把当天按圩日规则算客流 | 与真实圩日不重复叠加 |

不允许出现：成色加成、瑕疵清除、工时倍率、基础单价、升级折扣、好感购买。

## 3. 预留的两个活动

| id | 设想 | 0.1 |
|---|---|---|
| `act_osmanthus` | 中秋。桂花供应增加，游客权重略升 | `enabled: false` |
| `act_tusu` | 春节。只解锁一枚屠苏封签和一句账册文案，酒仍走现有酒路 | `enabled: false` |

屠苏不在 0.1 成为第五条酒路。要成为酒路，必须先改 `07` 和 `04`，而不是只开活动。

## 4. 时间

活动按现实日期开关，不按酒坊日。这是全作唯一读现实日期的地方：它只决定活动开没开，不让酒坊日跟着现实时间走。开启当天的下一次开坊生效，不追溯已经算好的当日客流。结束后下一开坊恢复。

## 5. 开关

默认配置 `activities: false`。为 false 时忽略全部活动行。测试用的打开方式只在开发构建里，发行构建没有隐藏按钮。

## 6. 验收

活动关闭时，28 日内的客流、价格、工时与没有活动文件时一致。见 `26`。
