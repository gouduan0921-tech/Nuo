# 项目目录与资源管理

版本：0.2 · 2026-10-01  
主责：仓库里东西放哪、谁可以改。玩法数字的权威仍是 `04`，表结构仍是 `05`。

## 1. 仓库顶层

```text
Nuo Brew/
  docs/            本套分册
  content/         JSON 配置，运行时只读
  tools/           build_docs_viewer.py（文档阅读器）、econ_handcalc.py（经济期望值手算），以后的 sim_economy.py 与校验脚本
  art_source/      Blender 源文件
  game/NuoBrew/    Unity 工程
```

`docs/` 不打进游戏包。`content/` 打进包，或由工程以只读方式引用同一份，禁止复制出第二套数字。

## 2. Unity 工程

```text
game/NuoBrew/Assets/
  Domain/          不引用 UnityEngine
  Application/
  Presentation/    场景、UI、音频挂载
  ContentLink/     指向仓库 content/ 的加载器，不放第二份表
  Art/             从 art_source 导出的 GLB、图集、动画
  Tests/           纯函数测试，编辑器里跑
```

场景 `yard` 只放布局和锚点。耗时、价格、概率不写进 Inspector。

## 3. Blender 源

```text
art_source/
  yard/
  rice/
  vessels/
  characters/
  export/          导出的 GLB，再拷入 Unity 的 Art/
```

源文件不进玩家包。导出步骤见 `17` §4。

## 4. 归属

| 改什么 | 先改哪里 |
|---|---|
| 规则 | `docs/` 主责分册 |
| 数字 | `04`，再落到 `content/` |
| 字段 | `05`，再落到 `content/` |
| 模型 | `art_source/`，再导出 |
| 存档字段 | `21`，再改 Domain |

玩法讨论不写进场景名、材质名或临时代码注释里当成新规则。

## 5. 版本

- 文档版本写在每份文首。
- 存档 `schema` 见 `21`。
- 内容表不另编号。表和 `04` 不一致时，加载失败，见 `05` §4。

## 6. 新增一件内容的最小步骤

1. 在主责文档写清它属于哪条已有规则。
2. 数字进 `04`，字段进 `05`。
3. 加 JSON 行，`enabled` 按首发范围设置。
4. 需要模型时走 `17` 的命名和预算。
5. 给 `26` 加一条能判定它的用例。

## 7. 禁止

- 在 Unity 场景里手填种子价、成色公式或客人权重。
- 把 `art_source` 的过程文件（未应用缩放的备份、渲染缓存）提交进 `Art/`。
- 首发包加载 `enabled: false` 的晚照、野生稻和另外三套风格的模型。
