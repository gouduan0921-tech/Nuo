# 技术架构

版本：0.2 · 2026-10-01  
主责：工程分层、酒坊日怎么步进、模块边界。玩法规则不在这里重写。帧率见 `04` §14。

## 1. 基线

- Unity 6 LTS，C#。
- 三维从 Blender 导出 GLB，按 `17` 导入。
- 首发内容在 `content/` 的 JSON。Unity 场景不存放第二套价格和耗时。
- 领域程序集不引用 `UnityEngine`。判定可以在没有场景的测试里跑完。

首发锁 Unity 6，是为了在电脑上稳定跑院景，并把同一套纯逻辑留到以后的移动端。稻浪、酒液、蒸汽都走网格、着色器和粒子，不依赖流体解算。

## 2. 分层

```text
Content        JSON 加载与校验，见 05
Domain         时间、天气、田、批次、成色、五味、客人、存档对象
Application    开坊、推进、收工、写盘
Presentation   场景、镜头、特写、账册、音效
```

Presentation 把点击收成命令：`TendPlot`、`Harvest`、`FormBatch`、`Assign`、`ConfirmSteam`、`Stir`、`Shelve`、`SetPrice`、`ReserveForOrder`、`Gift`、`Advance`、`EndDay`。命令进 Application。视图不改成色。

## 3. 酒坊日步进

### 3.1 开坊

按顺序：读天气和预报、老周报价、批购牌、氛围与客流、客人到达时刻、写当日账页、存盘。  
这一步不推进工时。玩家还没操作时，退出游戏再进，开坊结果不变。

### 3.2 推进

`Advance` 走到 `02` §2.2 的下一个交接点。每个整点结算时：

- 计时站按天气速度扣剩余工时。
- 要人的站若有人，扣工时；没人则停。
- 窗口开始或结束时抛出事件。结束且未搅，记 `stir_miss`。
- 客人到点则尝试成交，规则见 `08`。
- 写盘。

蒸甑特写期间不调用推进。确认之后才开始蒸的工时。

### 3.3 收工

第 8 工时结算完后进入收工。`EndDay`（一键收工）等于连续推进到第 8 工时，途中交接点照常结算，见 `02` §2.2。收工时：田 +1 阶、天气灾、家曲回复、开销、委托与批购到期、三行日结、`dayIndex + 1`、存盘。  
收工不是单独场景。次日仍在同一院子。

## 4. 模块

| 模块 | 职责 |
|---|---|
| Clock | 工时、交接点 |
| Weather | 种子化天气与预报 |
| Paddy | 阶段、照料、品相 |
| Batch | 酒路、工站、瑕疵 |
| SteamJudge | 三条参数对目标带 |
| Ferment | 窗口、搅缸 |
| Quality | 成色与败酿线 |
| Taste | 五味 |
| Shop | 客人、标价、批购 |
| Atmosphere | A、客流、moodK |
| Save | schema 1 的读写 |
| ContentDb | 表校验 |

随机只来自 `hash(profileId, dayIndex, channel)`。`channel` 用固定字符串，如 `weather`、`guest`、`supply`。读档不重掷。禁止在成交时再叫一次无种子随机。

## 5. 场景

首发一个场景 `yard`。酒窖是下沉一阶，泉池门默认不加载。  
镜头远时可以不画饭床形态键和远处粒子，数据层仍持有全部批次。

## 6. 错误

- 表校验失败：停在标题，列出第一条错误。
- 存档 schema 不符或含未启用篇章：不进入院子，提示另存备份。
- 命令非法（家曲不足、窖位不足）：拒绝并给一句原因，不部分扣料。

## 7. 测试钩子

Domain 的公开函数接受状态和命令，返回新状态和事件。`26` 的纯函数用例不启动 Unity。模拟器以后放在 `tools/sim_economy.py`，读同一份 JSON。
