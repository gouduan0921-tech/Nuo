# 前柜、客人与圩日

版本：0.2 · 2026-10-01  
主责：谁来买、怎么匹配、为什么成交或离开、老周的批购怎么交货。价格公式见 `04` §9。客流和溢价结构见 `13`。人物委托见 `16`。

## 1. 两条销路

- 前柜：当天客人一单一件，看酒路、成色和标价档。
- 批购：老周挂在河埠的木牌上，要若干件同一酒路，有交期和定金。

败酿可以上架，但首发客人的目标酒路都不包含败酿。败酿的销路是饲料抵开销，或偶尔以让利挂着等活动；活动未开时，默认没有人买。

## 2. 前柜

### 2.1 展位与后仓

展位数量见 `04` §4。后仓里的酒客人不看见。玩家把酒从后仓拖到展位，拖回去也行，不耗工时。  
一件酒同时只在一个地方：后仓、展位，或「留给批购」。留给批购的件不能上架，也不能送人或交委托。

入夜（工时 7–8）不生成新客人。白天已经进门、还没说话的客人会在入夜前说完。

### 2.2 标价档

上架时选让利、平价或讲究。改档立即改价，公式见 `04` §9。当日氛围已经算完，改布置不改今天的 moodK；改档会改 tierK。

## 3. 客人

### 3.1 当日客人从哪来

开坊时：

1. 按 `13` 算出客流。
2. 用 `hash(profileId, dayIndex, slot)` 从客人池抽满人数。
3. 给每位客人一个到达工时。范围和同一工时的人数上限见 `04` §10.2。

权重见 `04` §10.2。茶客在清酒未解锁时，目标酒路改为米酒。游客只在圩日加入。

### 3.2 客人亮出什么

走到柜台时，气泡只说三件事里的两件：想要的酒路、在意的那一味、能接受的标价档。在意的一味见 `04` §10.2 的「在意」列（街坊看甜、茶客看净、行商看醇、游客看香）。

不显示匹配分。

## 4. 匹配与成交

有人手在前柜，客人才会买。当家不算站柜的人，见 `16` §3。没人时客人等到下一个工时，仍没人就离开，主因是「柜上没有人」。

对展位上每一件算：

```text
pathOk    = 酒路在客人的 pathIds 里
qualityOk = quality >= minQuality
tierOk    = 标价档在客人的 tiers 里
tasteOk   = 在意的那一味 >= tasteOk 阈值（04 §10.2）
```

成交顺序：

1. 没有 `pathOk` 的件，跳过。
2. 在剩下的件里，去掉 `qualityOk` 或 `tierOk` 失败的。
3. 若一件不剩，客人离开。主因按这个优先级取第一条：酒路不对、成色不够、标价不合。
4. 剩下的件里，优先 `tasteOk`。若都没有 `tasteOk`，仍可买成色最高的那件，离开理由不触发。
5. 并列时买成色高的。再并列时买先上架的。

卖出后从展位移除，加钱和声望，见 `04` §10.3。一件客人只买一件。

街坊的最低成色是 36，正好卡在败酿线之上，所以合格的甜酒酿他们会拿，败酿他们不拿。

## 5. 批购

### 5.1 木牌

从第 3 日起，开坊时若木牌空着，按等级抽一张。各级的酒路、件数、交期、定金、成色要求见 `04` §10.5。

同一天只挂一张。玩家可以不接。接了定金进账，交期从次日开始数。

### 5.2 交付

交期当天收工时结算。先用「留给批购」的件，不够再从后仓按成色从低到高补，只取同酒路、成色达标的件。凑够件数即算交齐。玩家也可以在交期内任何一天提前交。  
交齐：按 `04` §9 的批购单价结算每件，定金算在总价里（尾款 = 总价 − 定金，最少 0）。声望 +3。木牌次日开坊可以再挂新的。  
逾期：声望 −2，退回定金（文不足时扣到 0），木牌清掉。酒仍在玩家手里。

### 5.3 为什么值得做

批购不看标价档和五味，适合把平价米酒成批送出去。它占用交期里的库存，前柜会少几件可卖的。圩日前一天若交期重叠，玩家要决定留甜酒酿给游客，还是把坛装酒送给老周。

## 6. 常驻委托

委托的触发和对话在 `16`。销售系统只负责：委托要的那件酒从后仓扣除，奖励按 `orders.json` 发放，数字见 `04` §10.5。

## 7. 日结

三行里的「柜」使用当日事件，不重新随机：

- 卖出：酒路、成色档（低于 50 / 50–69 / 70 以上）、客人名。
- 离开：主因一句。
- 批购：还剩几日，或今天交了、逾期了。

## 8. 边界

- 不还价。
- 不讨价到小数。
- 客人不因酒名或封签色改变成交。酒名只进酒谱和酒帖。
- 不设玩家之间的市场。
